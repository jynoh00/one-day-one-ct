# One Day, One CT

> 하루에 하나의 코딩 테스트 문제를 풀고, 풀이 과정과 배운 점을 기록

정답을 맞히는 것이 목표가 아닌 문제를 분석한 과정, 선택한 알고리즘, 개선할 점을 회고하며 기록하는 것을 목표로 합니다.

## 1. 목표

- 하루에 최소 한 문제 풀이하기
- 풀이의 시간·공간 복잡도 분석하기
- 해결 과정에서 알게 된 내용을 기록하기
- 다른 풀이와 비교하며 개선점 찾기
- 꾸준한 문제 해결 습관 만들기

## 2. 진행 방식

1. 문제의 조건과 요구사항을 분석
2. 사용할 자료구조와 알고리즘을 설계
3. 직접 코드를 작성하고 테스트
4. 시간·공간 복잡도를 분석
5. 풀이 과정과 개선점을 회고

## 3. 디렉터리 구조 예시

```text
one-day-one-ct/
├── README.md
└── problems/
    └── 2026/
        └── 07/
            └── 2026-07-10-problem-name/
                ├── README.md
                └── solution.cpp
```

각 문제 디렉터리는 다음 파일로 구성합니다.

- `README.md`: 문제 정보, 풀이 과정 및 회고
- `solution.*`: 제출한 정답 코드

## 5. 풀이 및 회고 형식

각 문제의 `README.md`는 다음 형식을 사용합니다.

````markdown
# 문제 이름

## 문제 정보

- 플랫폼:
- 문제 링크:
- 난이도:
- 사용 언어:
- 풀이 날짜:

## 문제 요약

문제에서 요구하는 내용을 간단히 정리합니다.

## 접근 방법

문제를 해결하기 위해 생각한 과정과 선택한 알고리즘을 작성합니다.

## 풀이

```text
정답 코드를 작성합니다.
```

## 복잡도

- 시간 복잡도:
- 공간 복잡도:

## 회고

### 잘한 점

-

### 어려웠던 점

-

### 새롭게 알게 된 점

-

### 개선할 점

-
````

## 6. 커밋 규칙

```text
solve: 문제 풀이 추가
docs: 풀이 설명 및 회고 수정
refactor: 기존 풀이 개선
fix: 풀이 오류 수정
```

예시:

```text
solve: 백준 1000번 A+B 풀이 추가
docs: 이분 탐색 문제 회고 작성
refactor: 두 수의 합 풀이 복잡도 개선
```

## 7. 원칙

- 충분히 고민하는 과정을 거친 이후에도 모르겠으면 힌트나 다른 풀이를 확인, 최소 1시간
- 정답 코드뿐만 아니라 문제 해결 과정을 기록
- 다른 풀이를 참고했다면 이해한 내용으로 다시 정리
- 풀지 못한 문제도 시도한 방법과 막힌 이유
- 완벽한 기록보다 꾸준한 기록

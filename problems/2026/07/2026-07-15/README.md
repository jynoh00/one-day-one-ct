## 문제 요약

- 전화번호를 담은 배열 `phone_book` 매개변수
- 어떤 번호가 다른 번호의 접두어인 경우가 하나라도 있으면 `false`, 없으면 `true`
    - 접두어가 있으면 : `false`
    - 접두어가 없으면 : `true`

- 제한 사항
    - phone_book의 원소는 1~1_000_000
    - 각 원소의 길이는 1~20
    - 중복 없음
    
- 의문
    - 내부 원소는 string 형식인데, 문자열에 공백이 포함되어있나


## 접근 방법

1. 브루트 포스 복잡도 고려

```
119의 접두어 : 길이 3
    1, 11
97674223의 접두어 : 길이 8
    9, 97, 976, 9767, 97674, 976742, 9767422
        
=> 길이 N이면 -> 가능한 접두어 개수는 N-1개
    
전체 for문 순회해서 각 접두어들을 만들고 ... -> 오래걸림
O(N(N-1)) => O(N^2), 최대 1조 연산 (N^2 최댓값 1_000_000 * 1_000_000)

=> X
```

2. 정렬 생각 (접두어)

```
크기 순 정렬 (<- 뒤 원소가 앞 원소의 접두어가 될 수 없으니까) 진행
이후 정렬된 벡터를 순회하여 조건을 검증해보자
```

3. 시간 복잡도 개선, 알고리즘 선정

```
기존 브루트포스의 경우 O(N^2)이 나왔는데, 이를 개선하기 위한 방법 고민
-> 결국 이 문제는 배열에서 두 원소를 골라 접두어인지 판별하는 과정이 핵심 로직
    => 두 원소를 비교하는 방식 중 선형 시간 복잡도를 가지는 알고리즘 -> 투포인터 사용
```

## 풀이

```cpp
bool solution(vector<string> phone_book) {
    init();
    
    sort(phone_book.begin(), phone_book.end());
    bool answer = solve_2(phone_book); // 사전순 정렬 적용

    return answer;
}

bool solve_2(vector<string> phone_book) {
    if (phone_book.size() == 1) return true;

    for (int i = 0; i < phone_book.size(); i++) {
        if (i == phone_book.size() - 1) continue;
        if (!my_compare(phone_book[i], phone_book[i + 1])) return false;
    }

    return true;
}
```

오름차순 정렬 적용 이후, 투포인터 방식으로 두 원소를 비교하고자 초기에 계획하였지만 실패

이유는 기본적인 숫자를 생각하고 정렬(sort)을 진행하였는데, 해당 입력은 `vector<string>`으로 들어온다.

따라서 정렬 알고리즘을 적용하면 문자열이기에 사전순으로 정렬이 이루어지고,<br/>
다음과 같이 기존 생각한 방식과 다른 반례가 존재하게 된다. `ex) 정렬된 벡터 [12111, 123]`

따라서 접근 방식에서 고려한 조건인 `크기 순 정렬 (<- 뒤 원소가 앞 원소의 접두어가 될 수 없으니까) 진행`이 실패하게 된다.

이에 `solve_3` 함수에서 문자열을 숫자로 변환하고, 정렬을 진행하는 방식으로 처리해보려 했으나,<br/>
개별 원소(문자열)의 길이가 최대 `20`이었기에, int 범위로 변환은 불가능, `long long`으로 변환해야했다.

해당 과정으로 변형한 `solve_3`를 진행하며 풀이에 대한 의문이 들었고, 다시 처음으로 돌아가

사전순으로 정렬하게 되면, 결과적으로는 양옆에 붙어있는 원소들은 문자열 초반 접두어가 동일함이 떠올랐다.

이에 양옆 문자열을 조회하고 한 번의 for문 순회로 O(N) 선형 시간의 탐색을 하여 결과를 출력하는 `solve2`로 정답을 작성했다.


## 복잡도

- 시간 복잡도: O(NlogN + N) = `O(NlogN)`

## 회고

### 잘한 점

- 브루트 포스(O(N^2)) -> 시간 복잡도 문제 파악 -> 투포인터(O(N)) : 시간 복잡도를 개선하는 일련의 생각 과정
- 정렬 알고리즘에서 숫자형으로 잘못 생각했던 것을 디버깅 과정에서 찾아낸 것

- 사용 언어: C++

## 문제 요약

- `N`이 주어질 때 `N!`의 가장 뒤에 붙는 연속된 `0`의 개수를 구하라
- `1 <= N <= 10^9`, 시간 제한 `1초`


## 접근 방법

1. 일의 자리 곱 연산

`6!`을 예로 들어보면, `6*5*4*3*2*1` => `1*2 = 2, 2 * 3 = 6, 6 * 4 = 24, 24 * 5 = 120, 120 * 6 = 720`

순차적으로 곱 연산을 진행하는데, 이때 나타난 가장 뒤에 붙는 `0`은 추후 어떤 수와 곱해져도 `0`으로 남아있는다.

마지막 `0`이 등장하는 조건 : 일의 자리끼리의 곱이 `% 10 == 0`이라면 마지막 0의 개수를 증가하는 방식으로 문제를 처음에 풀이하였다.

<br/>

- `이전 측정 수` * `이번 숫자` = `연산 결과`, `측정 수`
- `측정수` = 연산 결과의 0이 아닌 가장 작은 자리 수
- 연산 결과가 10의 배수면 카운트 증가

```
1 * 2 = 2 ... 2 -> 0
2 * 3 = 6 ... 6 -> 0
6 * 4 = 24 ... 4 -> 0
4 * 5 = 20 ... 2 -> 1 // 카운트 증가 <- 연산 결과가 10의 배수
2 * 6 = 12 ... 2 -> 1
2 * 7 = 14 ... 4 -> 1
4 * 8 = 32 ... 2 -> 1
2 * 9 = 18 ... 8 -> 1
8 * 10 = 80 ... 8 -> 2 // 카운트 증가 <- 연산 결과가 10의 배수
2 * 11 = 22 ... 2 -> 2
2 * 12 = 24 ... 4 -> 2
4 * 13 = 52 ... 2 -> 2
2 * 14 = 28 ... 8 -> 2
8 * 15 = 120 ... 2 -> 3 // 카운트 증가 <- 연산 결과가 10의 배수
2 * 16 = 32 ... 2 -> 3
...
```

다만 본 방식의 경우 다음과 같은 반례가 존재하였다.

이전 `측정수 = 4`, `이번 수 = 25` => `연산 결과 = 100` <- 카운트가 2번 증가해야한다.

이를 다음처럼 해결하여 보았지만,

```cpp
long long result = last_num * i;

while (result % 10 == 0) {
    count++;
    result /= 10;
}

last_num = result % 10;
```

본 방식은 결과적으로 문제의 핵심인 소인수 분해 관점에서 이전에 남아있던 `2`나 `5`을 고려하지 못했다.

`124!`의 경우 `4 * 125 = 500`의 경우 `0`이 두 번 카운트되어 증가되었겠지만 <br/>
실상은 연산의 결과에 적용되지 못했던 `2`가 `125`에서 0을 만들지 못한 `5`와 함께 곱해져 실제는 `0`이 `3`번 증가되어야했다.

2. `10`을 만드는 조건

해당 문제는 10을 만드는 소인수들이 얼마나 존재하는지가 해결의 접근 방법이었다.

10을 만드는 방법은 `1 * 10`, `2 * 5`로 정수 범위에서 나타낼 수 있는데 `1 * 10`의 경우 `1 * 2 * 5`로 분해되기에

사실상 해당 곱셈식(팩토리얼) 내의 `2`와 `5`의 개수를 측정하여 만들어지는 쌍의 개수를 구하면 되는 문제였다.


## 풀이

```cpp
int solve() {
    if (N == 1) return 0;

    for (int i = 2; i <= N; i++) {
        int tmp_i = i;

        while (true) {
            if (tmp_i % 2 == 0) {
                p.first++;
                tmp_i /= 2;

                continue;
            }
            if (tmp_i % 5 == 0) {
                p.second++;
                tmp_i /= 5;

                continue;
            }
            break;
        }
    }

    return min(p.first, p.second);
}
```

문제 해결을 위한 생각 전개가 잘못되었다.

숫자 가장 뒤에 0이 추가되는 경우를 10이 곱해질 때라는 생각을 먼저 했더라면 쉽게 풀었을 것 같다.


## 복잡도

- 시간 복잡도: `O(N)`

### 잘한 점

- 나름의 논리를 세우고 알고리즘을 전개하였다.

### 어려웠던 점

- 첫 풀이에서 조건문이 많아져 괄호가 늘어나니, 괄호 검사 디버깅에도 시간이 엄청 오래걸렸다.
- 첫 생각을 잘 잡았으면 엄청 쉽게 풀었을 것 같아 아쉽다.
